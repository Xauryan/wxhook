# 应用集成

入口为 `/apps`，使用既有 shadcn-admin 外框与黑白灰主题，不再展示第三方示例连接卡片。

## 首批功能

- 好友自动通过：按当前微信账号保存开关，处理启用之后的新入站 37 类型好友申请。可配置通过后的单条文本回复，只有当前账号源通讯录确认好友关系后才发送。
- 群聊自动拉人：一组私聊关键词与目标群配置；去除首尾空格后完整匹配。必须为当前好友的入站私聊，保存和每次执行时重新读取账号绑定的源通讯录、群管理权限和成员名单。已在群内跳过，同一好友和目标群 5 分钟内不重复提交。
- 红包秒抢：读取并操作既有 `hb_cold.disable` / `hb_cold_open.disable`。原生进程级，不按账号隔离；保留已有延迟与实验快车道配置。控制文件回读不代表 DLL 已完成领取，也不承诺网络时延。
- 红包卡片的“配置红包秒抢”可保存领取延迟。输入 `300` 为固定 300ms，`300-800` 为每次随机 300～800ms，取值范围为 0～600000ms。配置写入 `hb_cold_delay.json` 后由原生线程自动加载，后续任务在发起领取请求前等待。

## 权限与原生状态

- 当前源库 `chat_room.owner` 可可靠核验群主。尚无经核实的管理员名单协议，非群主显示“权限未确认”并禁止选择，绝不猜测 `ext_buffer` 成员位标志为管理员。后续有可靠管理员来源后再扩展。
- 当前原生好友自动模式可能已由旧控制器启用。首次加载只查询并如实显示，不修改；用户显式保存好友配置才关闭旧原生自动模式，并由新账号级执行器接管。旧模式未确认关闭时不保存；被其他控制器重新打开时拦截重复执行。
- 红包控制目录必须与当前微信进程加载的桥接 DLL 目录、进程创建时间和新鲜原生工作状态相符，否则显示未知并禁止修改。
- 新好友/群聊规则默认关闭。启动不接管、不导入旧自动化规则，不修改既有通知服务、回执或历史记录。

## 运行和持久化

- 新服务只在既有 `WECHAT_CHAT_ONLY=1` 模式运行，避免与旧 `FriendAutomation` 双执行。使用项目 `.cache/integrations.sqlite` 和独立进程锁。
- 以现有 `live_messages` 实时账本为输入。保存记录启用游标；服务启动从最新游标开始，不回放停机期间的消息。超时 120 秒的事件不触发，待确认欢迎语最多等待 180 秒。
- 配置以账号、功能隔离，使用版本号阻止其他页面覆盖。执行记录持久去重；票据不存入新执行记录。受理、失败、未知、拦截分别展示，不将桥接返回当作已入群/已发送。
- 新用户未开启本页规则时后台只读新事件，不执行社交操作。重启取消未确认的旧欢迎语，不自动重试结果未知的发送或邀请。
- 修改 API 保留本机访问、Origin、活动账号校验。切换账号会卸载旧前端编辑状态；所有实际操作前再次检查账号。

## 接口

- `GET /api/integrations`：当前账号配置、原生状态、执行器状态、最近 20 条记录。
- `GET /api/integrations/groups?account=...&refresh=true`：当前账号群权限，只返回必要展示字段。
- `POST /api/integrations/friends` 和 `/groups`：`account`、`revision`、`config`。
- `POST /api/integrations/hongbao`：`account`、`enabled`、`expected_enabled`。
- `POST /api/integrations/hongbao/delay`：`account`、字符串 `delay_ms`、页面读到的 `expected_delay_ms`。校验范围、账号和控制目录，旧配置冲突返回 409。

## 验证边界

配置、权限、重复事件、账号切换、失败与未知回执采用隔离 SQLite 和模拟桥接测试。实际账号仅用于只读状态和群权限核验，不以真实加好友、欢迎消息、邀请或红包领取进行验收。
