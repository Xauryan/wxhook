# 一键解密快照与自动更新

在「数据分析」任一页面的「解密快照」卡片中，登录本机微信后点击「一键生成快照」；已有数据时为「一键更新快照」。无需手动提取密钥、输入目录或执行命令。当前支持 Windows 微信 4.1.9.23，其他版本会停止任务并显示原因。

页面显示核验、密钥、复制、解密、报告、统计索引、发布阶段，以及数据库、文件进度、已处理库数和已解析消息数。首次全量索引可能耗时较长，关闭页面不会取消任务。可主动取消后重新生成。重复点击返回运行中的同一任务。

「自动更新快照」默认关闭。开启时绑定当前账号，可选择每小时、每 6 小时或每天；应用后台运行且绑定账号在线时执行。离线或切换账号时等待，不改绑其他账号。失败后按所选间隔再次尝试。关闭开关停止后续调度，运行中的任务需单独取消。API 重启后恢复配置和任务进度。

## 数据与发布约束

- 从桥接端口所属微信进程及唯一打开的当前账号通讯录定位源目录，不接受前端传入路径或 PID。
- 对每个数据库及 WAL 检查复制前后指纹，变化时重试；合并已校验的已提交 WAL。不写微信数据库、不 checkpoint、不要求关闭微信。各库分别捕获，不承诺跨库的同一事务时刻。
- 新提取密钥使用 Windows DPAPI 绑定当前用户保存。接口、页面及日志不返回原始密钥。旧 CLI 明文 manifest 仍兼容。
- 必需库及所有 `message_N.db` 必须通过解密验证。其他附属库无法解密时列入 `unresolved`，页面显示库名及数量，不报为全部成功。
- 对明确的原生 FTS 分词器兼容错误，记录 `skipped_unsupported_tokenizer` 或 `skipped_missing_extension`。逐页密码学验证仍执行，此类库的 SQLite 完整性检查不计入通过数，页面独立提示。普通数据库损坏仍停止发布。
- 所有消息分片合并解析；有服务器消息 ID 时按会话及服务器 ID 去重，无服务器 ID 时保留各分片本地消息。会话统计按时间重新排序。
- 统计索引在独立进程构建并校验，完成后原子替换报告指针。失败或取消不替换旧报告，旧快照及已打开的旧索引保留。任务目录保存 `previous-report.json`。
- 启动前按源库及 WAL 总量约四倍加 1 GB 检查可用空间。暂不自动删除历史快照，避免影响其他读取者。

## 本地接口

| 接口 | 行为 |
| --- | --- |
| `GET /api/analysis-snapshots` | 能力、自动更新配置和公开进度 |
| `POST /api/analysis-snapshots` | 传入当前 `account`，账号不符返回 409，重复点击复用任务 |
| `POST /api/analysis-snapshots/{id}/cancel` | 取消与发布共用跨进程锁，已发布结果不回滚 |
| `POST /api/analysis-snapshots/automation` | `account`、`enabled`、`interval_minutes`（60/360/1440）、`revision`；版本冲突返回 409 |

接口仅允许本机及受信任本地页面操作。任务及配置位于 `.cache/analysis-snapshots/`。短启动进程派生独立执行进程，避免随 API 守护进程的普通子进程清理终止。重启后任务进程消失会标记中断并允许重新生成；已发布但成功状态未写完时，根据报告指针恢复状态。

自动化测试覆盖启动去重、账号变化、任务恢复、配置冲突、调度间隔、来源限制、发布前验证、失败及取消回退、附属库缺失、分片去重和前端交互。模拟任务证明流程与边界，真实验收另以当前账号的报告、索引及页面读回确认。
