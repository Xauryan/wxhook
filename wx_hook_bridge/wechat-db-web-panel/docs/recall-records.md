# 撤回消息记录

在 `/chats` 的微信工作台导航点击 **撤回记录**。收到撤回通知后，后端自动保存独立记录；页面通过实时事件更新，并每 15 秒补查一次。支持按会话、发送者和原文搜索，按需加载更早记录。

每条记录包含会话、发送者、撤回通知、消息 ID 和已捕获的原文。点击 **查看聊天位置** 会打开对应会话并高亮原消息；原消息没有入库时定位撤回通知。两者均不可定位时只提供 **打开聊天**。

原文必须在撤回前被接收或在已有本地历史中读取过。原消息晚于撤回通知到达时可以补充原文，但不会恢复聊天里的撤回占位。非文本消息保存可读标题、摘要等已有信息，不自动下载媒体。没有捕获原文时明确显示 **原文未捕获**，不会推测内容。

原生撤回 Hook 有时返回 `revokeTime=0`。此类通知按接收时间进入聊天，独立撤回记录的真实撤回时间保持未知，页面显示 **发现于**。已有接收缓存会在后端启动时补收；旧缓存缺少接收时间的记录显示本次发现时间。

记录保存在 `.cache/live_chat.sqlite` 的 `chat_recalls`，按 `(account, session, server_id)` 去重，独立于聊天展示和历史同步。启动迁移只读取现有接收账本，不扫描全部历史消息。账号切换后接口校验当前微信身份，页面清理旧账号缓存。

## API

- `GET /api/chat/recalls?account=<wxid>&q=<关键词>&limit=50&before=<记录ID>`：返回 `items`、`total`、`next_cursor` 和 `revision`。
- `GET /api/chat/sessions/<username>?account=<wxid>&around=<server_id>`：定位原消息。
- `GET /api/chat/sessions/<username>?account=<wxid>&around_id=<message_id>`：定位本地账本内的撤回通知。
- `/api/chat/events` 的 `chat.recalls` SSE 事件：`account`、`revision`，用于通知页面重新读取记录。

需要电脑微信、原生桥接、接收转发和面板后端持续运行。消息未进入 Hook、桥接离线或接收已丢弃时，页面无法保证收集。手机自己发送的同步消息仍受现有 Hook 覆盖范围限制。

## 验证

后端专项测试覆盖原文保存、重复通知、重启补收、通知先到、账号及会话隔离、大整数 ID、缺失时间戳、搜索分页和接口身份校验。前端测试使用隔离的模拟 API 验证原文展示、实时刷新及原消息/通知定位，不作为真实微信收消息证据。
