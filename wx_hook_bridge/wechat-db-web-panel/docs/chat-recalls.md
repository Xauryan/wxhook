# 撤回记录

在“微信聊天”工作台的左侧工具栏点击“撤回记录”。页面按记录顺序展示会话、
发送者、撤回通知、时间和已捕获的原消息，支持搜索、刷新及加载更早记录。

点击“查看聊天位置”会打开对应会话，读取目标消息前后的上下文并高亮目标。
目标不在当前加载范围或最新 60 条消息中时，也会单独读取对应窗口。
原消息未捕获时优先定位撤回通知；当前缓存没有可定位的消息时显示“打开聊天”。

## 保存与显示

- 已捕获原文保存在独立的 `chat_recalls` 表中，聊天中的撤回占位不会覆盖保存的原文。
- 记录按账号、会话和消息 ID 隔离，重复 Hook 通知不会重复建记录。
- 原消息晚于撤回通知到达时补充原文；历史同步不会把聊天占位改回原文。
- 启动时从已有 Hook 原始账本补充可核验的记录，重启保留记录。
- 未收到撤回前的原消息时显示“原文未捕获”。非文本消息显示已有摘要或文件名。
- 撤回时间未知时显示“发现于”，使用收到通知的时间，不将未知时间显示为撤回时间。
- 新增记录通过 `chat.recalls` 事件刷新，断线恢复及定时读取补充遗漏更新。

## 接口

`GET /api/chat/recalls?account=...&q=...&before=...&limit=50`

返回当前账号的记录、总数、下一页游标和版本。`jump_server_id` 指向已缓存的原消息，
`jump_message_id` 指向原消息缺失时仍可定位的撤回通知。消息 ID 使用字符串传递。

`GET /api/chat/sessions/{username}?account=...&around=...`

按消息服务器 ID 读取上下文。`around_id` 可按本地消息行 ID 定位撤回通知，
同样限定当前账号和会话。

新增接口需要面板 API 进程加载更新后的源码。测试数据与真实 Hook 数据分别验证；
未进行真实发送或人为撤回来生成测试消息。
