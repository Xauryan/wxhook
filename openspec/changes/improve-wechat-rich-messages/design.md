## Context

当前实现已经有账号隔离的消息账本、本地媒体索引、图片解码和音视频转换。已核实腾讯新闻的 `mmreader` 消息使用 `local_type=1`，现有文本分支提前返回导致 XML 直接展示；媒体描述固定优先缩略图，弹窗也沿用同一地址。前端尚无微信内置表情转换。

## Goals / Non-Goals

**Goals:**
- 保留微信式左右气泡、历史定位、增量合并和账号隔离，完善媒体打开与图文展示。
- 图片按原图、预览、缩略图分级，语音和视频点击后播放，文件整卡打开。
- 消息字段仅作为数据处理；识别明确的公众号结构而不是把普通文本中的尖括号当作 HTML。
- 用真实本地只读数据核对解析，以隔离 fixture 验证交互和异常。

**Non-Goals:**
- 不修改微信源数据库，不发送测试消息，不改变发送与通知工作流。
- 不下载缺失的聊天附件，不添加任意 URL 后端代理或强制触发微信下载。
- 不实现 Office 全格式转换、在线编辑或账号间资源共享。

## Decisions

1. 在 `present_content` 的普通文本返回之前识别明确的 `mmreader` 和 `appmsg/mmreader` 结构；兼容 `topnew/newitem` 及 `item` 数组，按原顺序生成 `articles`，相同标题与地址去重。普通文字仍逐字保留，更新历史展示版本重新导入派生账本，不删除原始历史。
2. 图片列表使用可用预览，点击通过媒体描述的 `original/preview/thumbnail` 顺序打开清晰版本；失败则尝试下一级并如实显示当前画质。媒体描述在首选文件坏掉时继续尝试同类型资源；视频缩略图不能被当作视频播放。
3. 语音使用原生 audio 的播放能力与自定义可聚焦气泡；视频使用封面按钮及 Radix 弹窗中的原生 controls。文件卡片打开同一弹窗，支持安全图片、PDF 和纯文本预览。已核实当前附件多数为 XLSX，因此增加 XLSX、DOCX、PPTX 的有界只读内容预览，仅读取 ZIP 内的 XML，不执行公式、宏、外部引用，不声称完整还原 Office 排版；其他格式明确提供下载。
4. 公众号封面直接通过浏览器加载安全 HTTP(S) 地址并设置 `no-referrer`，链接以 `noopener noreferrer` 新窗口打开；不新增后端任意 URL 请求能力，不使用 HTML 注入。失败封面有替代状态，文章标题仍可点击。
5. 内置表情以确定的名称映射呈现，支持中英文已知代码；文本分段渲染，不改数据库、不执行 HTML，未知代码保留。动态表情继续走本地媒体链路。
6. 沿用现有布局与颜色，只对媒体和图文气泡减去不必要的边框与绿色底色。保留键盘操作、焦点、关闭按钮、移动端宽度与减少动画设置。

## Risks / Trade-offs

- [没有本地原图或微信未下载附件] -> 明确降级与提示，不将缩略图标注为原图。
- [本地 native 解码预算、音视频编解码缺失] -> 保留现有串行和上限保护，显示可重试的失败状态。
- [公众号远程封面过期或禁止外链] -> 封面占位和真实标题保留，文章可独立打开。
- [Office 等浏览器无法直接解码的文件] -> 显示文件元信息与下载，不执行内容、不伪造预览。
- [现有工作区有大量未提交实现] -> 只增量修改涉及消息呈现的文件，不清理或覆盖其他工作。

## Migration Plan

完成解析及交互测试后构建现有前端，更新当前本地容器；重启已确认的 Windows API 进程，保持相同配置、账号与账本。历史 schema 升级仅触发重新生成展示字段。记录浏览器、测试和真实数据验证边界，不自动提交、推送或归档。
