## Context

现有 `ActiveWechatRoster` 已验证桥接进程实际打开的通讯录，读取一致性副本，但仅保留发送对象名称；联系人图标只设置 `scope=contacts`。当前 contact 表包含拼音、备注、别名和扩展资料，chatroom_member 提供成员关联。已用当前账号 Abby 资料核对性别、签名、地区、添加来源和日期字段，共同群聊数据库关联结果为 2，吻合参考界面。

## Goals / Non-Goals

**Goals:**
- 真正独立的通讯录，包含无聊天记录的真实联系人，不混入群成员、服务帐号和历史陌生人。
- 真实资料展示、共同群聊跳转、通讯录管理与备注保存回读确认。
- 明确区分未提供资料、读取失败和暂无记录，不根据截图填数据。
- 保留现有微信聊天、消息媒体、草稿、账号隔离和本地部署方式。

**Non-Goals:**
- 不实现语音/视频通话、联系人删除、好友申请自动接受、完整朋友圈或视频号浏览。
- 不通过旧账号数据库、宽泛内存扫描或网络搜索补充个人资料。
- 不在验收中发送真实消息、修改真实备注或接受好友。

## Decisions

1. 扩展现有已验证通讯录的副本读取，在同一个 SQLite 快照提取白名单资料和共同群聊。使用独立派生表保存目录资料，发送对象表保持兼容。目录包含当前账号本人及源库标为好友的内置联系人微信团队；排除文件助手、支付等服务会话、公众号、群聊、删除记录和非好友成员。微信团队仅查看资料/会话，不提供备注修改。
2. 对当前版本 `extra_buffer` 做有界 protobuf 字段读取，只解析已核实的字段：2 性别、4 签名、5-7 地区代码、8 添加来源、41 添加时间。其他字段不猜测。朋友圈扩展区只可用于说明本地存在资料，不伪造朋友圈列表或 Finder 账号。
3. 目录资料与好友申请均先核验当前账号，再读取账号域内缓存。刷新同一账号的派生缓存不删除聊天、发送回执或其他账号数据。无新资料缓存时返回明确的加载状态，而不是空好友数。
4. 新的朋友使用当前账号已有一致性历史快照中的 FMessageTable（若存在），仅提供姓名、申请摘要、时间和已在通讯录中的状态；票据等敏感字段不输出。无来源时明确“本地申请记录尚未就绪”，不显示虚假的待接受数量。
5. 备注修改只允许当前已核验好友，使用已有 `/api/modifyRemark`。请求带原备注和请求 ID，检查原值冲突、防重复派发；返回成功后刷新实际通讯录并比对，未读回一致值只能报告“待确认”，不做乐观假成功。限制本机可信 Origin，并为用户保留重试/核对路径。
6. 微信导航增加 `view=chats/contacts`，与会话筛选 scope 解耦。通讯录提供字母列表、详情、管理表格、新朋友和共同群聊展开；发消息使用现有 Conversation，不复制发送链路。按当前账号隔离选择、搜索和查询缓存。
7. 沿用既有灰白微信布局、绿色选中图标和本地头像；资料分区、返回按钮、可聚焦控件和窄屏列表/详情切换与参考界面保持一致。

## Risks / Trade-offs

- [微信资料扩展字段随版本变更] -> 仅解析已核实字段，异常值留空并保留原始源库，不猜测来源或日期。
- [备注请求超时但微信可能已修改] -> 记录 pending/unknown 结果，禁止同请求 ID 盲重发，回读原始通讯录确认。
- [新朋友快照不含记录或未就绪] -> 返回来源状态，不假装完整实时好友申请列表。
- [未接入的朋友圈、视频号、通话] -> 明确未接入状态，不能伪装成功操作。
- [当前工作区已有大量未提交内容] -> 只增量修改本功能文件，保留所有现有改动和验收产物。

## Migration Plan

新增派生联系人及操作回执表，旧表与历史保留；后台下一次同步生成目录。通过隔离测试后构建并更新现有本地容器和 Windows API，核对账号一致、通讯录数量、真实资料以及聊天跳转。保留 OpenSpec，不自动归档或提交 Git。
