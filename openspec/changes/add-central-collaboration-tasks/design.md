# 简单任务协作中心

## Context

用户已明确：中心只是让成员看见任务、知道应该开发什么。代码评审与合并由所有者自行到 Git 仓库操作；中心不接收仓库事件或自动判断成果。

原方案中 GitHub App、Webhook、review/SHA 判断和对账队列均撤销。本文件是当前设计，以前的自动验收规则不再适用。

## Goals / Non-Goals

**Goals:** 统一任务池、明确负责人、多人协作、简单交付、人工确认、Git 邮箱署名。

**Non-Goals:** 代码评审平台、仓库权限管理、自动合并、绩效计费、多租户、外部登录、上传本机微信数据。

## Decisions

### 1. 中心与入口

```text
成员各自部署的原后台 /tasks 页面（保留完整侧栏与顶部栏）
                    |
       同源 /api/task-center 代理 -> https://jqr.47jsy.com -> 统一任务 API + PostgreSQL

Git 仓库：仅由人打开 PR 链接，系统不调用仓库 API。
本机微信：保持原有本机链路，与中心隔离。
```

任务页面直接嵌入现有 shadcn-admin 的 `/_authenticated/tasks/` 路由，不跳转、不使用 iframe、不创建第二套侧栏，也没有独立前端入口。页面内分类是内容区页签。后台存储服务可独立运行，但不代表独立用户界面。

本地 Vite（含 preview）及原 Docker Nginx 默认将 `/api/task-center` 代理到 `https://jqr.47jsy.com`，其他 `/api` 微信代理保持不变。每人打开的是自己的本地后台，任务共用云端存储；无需各自启动任务 API 或数据库。Vite 的 `TASK_CENTER_API_PROXY` 只用于明确的隔离开发验证，正式默认值不回落本地。

本地代理先校验写请求的 Origin 与自己的 Host/协议一致，原样保留 Origin 转发。中心接受自己的 HTTPS Origin 和标准回环来源（localhost、127.0.0.1、::1），仍检查 CSRF，不开放通配 CORS。中心为本地回环页面签发独立 `tc_remote_session` HttpOnly Cookie，路径仅 `/api/task-center`；直接访问云端仍用 Secure `__Host-tc_session`。代理只转发任务 Cookie，不上传本机微信或旧预览身份凭据。GET、写入、退出和 SSE 使用同一会话规则。

任务模块采用局部 QueryClient，邀请登录/退出不清空原后台聊天等功能的缓存。详情查询参数交给现有 TanStack Router，支持刷新、前进/后退及通过侧栏离开再返回。

### 2. Git 邮箱署名进入

- 成员只填写 Git 邮箱，不用密码、邀请或邮箱验证码，也不查询 GitHub。
- 邮箱统一去首尾空格并转小写，同一邮箱复用同一成员 ID。它是自填署名而非验证身份，页面明确说明。
- 已有 owner 会话和离线管理凭据保留，输入任何邮箱都不能获得 owner 权限。首位填写邮箱的人也不会自动成为管理员。
- 常规密码登录、邀请创建/接受接口和页面移除；保留历史字段，不根据用户名猜测邮箱或转移任务。
- 增量迁移增加 git_email 唯一字段。任务合作、完成权限与审计仍依据服务器的成员 ID 和 owner 会话，不相信请求中的 role。
- 保留会话、CSRF、Origin 校验和限流。停用相同邮箱后不得再进入，但此简易署名机制不能阻止别人自填其他邮箱，不宣称强身份验证。
### 3. 任务流程

```text
草稿 -> 待领取 -> 进行中 -> 待确认 -> 已完成
                            |
                         退回修改 -> 重新提交 -> 待确认
```

- 成员可以创建任务，创建人或所有者可以编辑范围和发布；取消与重开仍只属于所有者。内容包括月份、标题、目标、验收标准、优先级和截止时间。
- `created_by` 由服务端记录且不可修改，独立于负责人和协作者。创建不会自动认领或加入协作；“我创建”跨月份显示本人创建的任务，创建成功后直接进入自己的草稿详情。
- 发布时可暂时无人负责；成员原子认领，只能一个负责人，其他成员加入协作。
- 负责人分配轻量分工，协作者只能更新自己的分工。个人分工全完成也不会完成任务。
- 负责人转交须目标成员接受，所有者可说明原因直接重新指派。停用负责人不会删任务或随机换人。
- 负责人或所有者提交成果，必填说明与至少一个 HTTPS PR 链接；可一次填写多个链接。只校验安全 URL 形式，不发起网络请求、不验证作者或合并状态。
- 只有所有者能在待确认状态点击“确认完成”，可填写确认说明。退回修改必须写原因。记录确认人、时间、处理意见。
- 负责人可撤回待确认成果；退回后再次提交，旧成果和意见保留。仅保留简单提交记录，不再冻结 SHA、评审快照或必需/参考 PR 集合。
- 整体完成时间是所有者确认时间，不再是 Git 的合并时间。
- 修改待确认任务范围前先撤回成果；完成任务重开须写原因，旧确认记录保留，新工作必须重新提交后才能确认。
- 按北京时间组织月份，历史和跨月未完成任务保留，不自动清空。

### 4. 数据和接口

沿用任务聚合、任务成员/分工/讨论 JSONB、事件表和幂等回执。新增 git_email 唯一身份字段，已有 owner_user_id 管理身份不变。`20261011_task_creator` 增量添加任务创建人外键和索引，只从历史创建/复制事件回填，不猜测缺失身份。

任务 `deliveries` 只记录 id、说明、PR 链接、提交人/时间、处理状态、确认人/时间/原因。旧原型 `pulls/submissions` 和退役队列表不清除，但不再参与运行逻辑或由当前页面展示为有效验收结果。

API 前缀 `/api/task-center/v1`：

| 接口 | 用途 |
| --- | --- |
| `POST /auth/identify`、`/auth/logout` | 填邮箱进入及退出 |
| `GET /me`、`GET /members` | 当前用户与成员 |
| `POST /members/{id}/state` | owner 停用/恢复，记录原因 |
| `GET/POST /tasks`、`GET/PATCH /tasks/{id}` | 任务查询、创建、详情、范围修改 |
| `POST /tasks/{id}/actions/{action}` | 认领、协作、提交、complete、request-changes 等明确业务动作 |
| `GET /events`、`GET /tasks/{id}/activity` | SSE 更新、操作历史 |

任务操作仍有 expected_version 和 Idempotency-Key，避免同时认领和重复提交。确认的是页面当前版本的成果；负责人撤回/重提后，旧版本确认必须冲突，不允许误确认。

### 5. 实时和失败

业务变更与事件同事务提交，项目行锁使序号按提交顺序前进。SSE 只通知对象更新，客户端重新拉取；失败保留已加载数据与输入，断线重连并辅以 30 秒轮询。草稿及草稿事件只对创建人和 owner 可见，发布也不向其他人追溯开放草稿私有历史。成员停用会使长连接失效。

## Risks / Trade-offs

- PR 链接可能无效、无权限或尚未合并：这是人工核查的职责，页面不声称自动验证过。
- 邮箱可能被冒用：这是轻量署名模式，不验证归属；管理员权限不从邮箱获取。
- 历史 GitHub 原型数据：保留原表，不静默复用旧会话；owner 需离线初始化，原成员填写邮箱进入。
- 中心故障：任务暂不能更新，不创建分散的可写本地副本。

## Migration Plan

历史迁移保持不变，当前追加 `20261011_git_email`，仅添加邮箱字段及唯一约束。已有待验收的原型成果可转换为仅说明/链接的人工待处理记录；原 JSON 仍保留。迁移不删除任务、审计或历史确认，也不自动把 GitHub 账号认作管理员。

初始实现已完成隔离 PostgreSQL 和多身份浏览器验证。2026-10-11 用户单独授权 dig / jqr.47jsy.com 上线，正式库从空任务开始，不导入预览数据；后续补齐本地客户端默认接入。保留原本机微信链路和预览库，不提交、不推送。

## Open Questions

中心已授权部署到 dig 的 `jqr.47jsy.com`。普通成员从各自回环地址的原后台使用；所有者使用独立管理凭据。不需要 GitHub App 或仓库 API 配置。
