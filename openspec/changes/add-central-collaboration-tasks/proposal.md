## Why

私仓协作者需要知道项目缺什么、可以开发什么，以及任务由谁负责。任务中心应管理目标与协作，不应替代 Git 仓库的代码评审流程。

## What Changes

- 统一中心存储月度任务，一个负责人、多人协作，保留分工、讨论和历史记录。
- 成员可创建、查看、编辑和发布自己的任务，记录独立创建人；所有者仍管理全部任务。草稿仅创建人及所有者可见。
- 成员填写 Git 邮箱直接进入，不需要密码、邀请或验证码；邮箱仅作自填署名，不能获得管理权限。
- 负责人提交成果时仅填写说明和一个或多个 PR 链接。所有者自行查看代码仓库，再手动确认完成或填写原因退回。
- 删除 GitHub OAuth、Webhook、自动 PR 查询、评审/合并判定、后台对账和相关测试替身。
- 保留服务端权限、并发认领、幂等写入、审计和实时更新。取消所有者批准/合并的自动技术判据。
- **BREAKING**: 旧模拟登录和 GitHub 会话不能登录新中心；不自动把历史 GitHub 身份升级成新账号。

## Capabilities

### New Capabilities

- `task-center-identity`: Git 邮箱署名、owner 独立权限、成员停用/恢复。
- `monthly-collaborative-tasks`: 月度任务、负责人、协作者、分工、讨论与历史。
- `manual-task-acceptance`: 说明与 PR 链接提交成果、所有者确认/退回。
- `task-center-delivery`: 原后台任务管理页内集成、同源 API、实时更新和本地验证。

### Modified Capabilities

无已归档能力。本次替换尚未发布原型的自动验收方案，不保留两套完成机制。

## Impact

统一存储后端位于 `task-center/`，但任务 UI 必须直接显示在现有后台的“任务管理”菜单中；删除独立前端入口和外跳卡片，保留原侧栏、顶部搜索、主题及布局设置。邀请账号迁移保留历史数据，不影响本机微信启动或数据。

## Non-goals

不调用 GitHub API、不核查 PR 是否存在/批准/合并、不自动创建/合并 PR、不同步私仓成员、不提交或推送。服务器上线已单独授权到 dig / jqr.47jsy.com；成员仍从各自本地后台使用，不建设完整运维平台。
