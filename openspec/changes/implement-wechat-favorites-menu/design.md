## Context

当前账号存在 `favorite/favorite.db`，含 3 条 type=2 图片收藏；收藏标签与绑定表均为空。收藏原始附件和中图在 `business/favorite/data`、`business/favorite/mid`，实际为 V2 加密媒体，文件名不等于 XML 中的 dataid/fullmd5，不能直接按文件名猜测。现有 native 桥接文档与路由没有已验证的收藏新增/笔记写入能力。

## Goals / Non-Goals

**Goals:**
- 独立收藏工作区，真实搜索、分类、标签、来源、时间和安全预览。
- 保留源数据库与附件，只在项目缓存写入一致性副本与解码结果。
- 复用媒体的账号验证、串行解码和预算，不为收藏额外建立无限制 native 调用链。
- 缺失资源、状态不明、未下载或写入能力缺失均有明确反馈。

**Non-Goals:**
- 不修改微信源收藏库、不调用旧版本未验证偏移、不自动下载云端附件。
- 不把本地草稿称为微信收藏，不实现本轮未接入的新建笔记、标签编辑和删除收藏。
- 不将本地文件占用当作云端剩余容量；不硬编码截图中的 2 GB。

## Decisions

1. 独立收藏快照 worker 验证当前桥接进程与账号，复制/decrypt favorite.db 及已提交 WAL，在读取前后验证一致性。收藏刷新失败不阻塞聊天历史同步。派生收藏缓存按账号隔离，原始源文件不变。
2. 解析 `fav_db_item`、`fav_tag_db_item` 和绑定表，正文只按数据解释，不输出 CDN 密钥或执行 XML/HTML。已观察状态 flag=0 正常展示；未知状态不猜测，返回受限计数。标签只使用可识别的本地关联，未知操作状态提示受限。
3. 附件只在当前账号的收藏 data/mid 目录内匹配，忽略 temp/NoteCache。按记录摘要、大小和候选文件建立有界索引；加密图片经过既有媒体解码后校验内容摘要，匹配成功才交付。不同收藏的资源 URL 与版本令牌不可互换。
4. 抽出既有 ChatMedia 内部的已验证文件转换方法，聊天路径检查保持不变；收藏在自己的路径/记录校验后复用同一个媒体实例的缓存、锁和 native 调用预算。
5. 卡片懒加载中图/缩略图。点击卡片直接打开收藏详情，图片优先原图，音视频用浏览器控件，文件复用安全预览及下载；复合收藏可切换其真实附件。没有原图时明确降级，不称为原图。
6. 收藏视图拥有独立搜索/分类/标签状态，微信菜单图标与仪表盘链接解耦；账号变化会移除旧收藏查询及选择。页内保留全部收藏、图片与视频、标签、刷新和响应式返回导航。
7. 只报告能确认的附件大小与来源更新时间。新建笔记按钮明确未接入，云端容量为未获取，不展示虚假的保存结果或剩余配额。

## Risks / Trade-offs

- [文件映射或摘要不匹配] -> 有界候选验证，无匹配则报告未找到，绝不按最近文件或同尺寸盲选。
- [微信解码预算耗尽] -> 共享现有保护与持久缓存，错误不伪装成功，不循环重试 native。
- [收藏库或 WAL 在读取时更新] -> 使用一致性副本并有限重试；失败保留上次验证数据和明确错误。
- [未知收藏/标签状态] -> 提示解析范围，原始数据仍保留；不虚构空列表或关联。
- [浏览器不支持附件格式] -> 提供安全下载或显式不可预览状态，不执行附件代码。

## Migration Plan

新增账号域内收藏派生表，保留原有聊天与通讯录表。通过隔离回归、构建和真实只读资源验收后更新现有本地容器及 Windows API。保留 OpenSpec，不自动归档或提交 Git。
